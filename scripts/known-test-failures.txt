# 已知失败用例基线（历史债锚定）
#
# 用法：scripts/check-xcresult-failures.sh 把本次 xcresult 的失败用例与本文件比对，
# 命中基线 → 只告警放行；基线外的新增失败 → 直接判红。于是不再出现"CI 绿但用例在失败"，
# 也不必一次性修完所有历史债。
#
# 格式：`<label>:<TestClass>/<testMethod>`，label 与 ci.yml 传入的一致（iOS / macOS / UI）。
# macOS 两个分片共用 macOS label；用例换分片不影响本文件；方法名写不写 () 都识别。
# 三种粒度，从紧到松——通配范围越大掩盖越多，能收紧就收紧：
#   `macOS:Foo/testBar`        精确一条，用于确定性失败（断言写错、标识符缺失）
#   `macOS:Foo/testBarBaz*`    同组飘移豁免：CamelCase 前两词相同的超时/崩溃用例成组锚定
#   `macOS:Foo/*`              整类豁免，只在该类过半方法都在飘时使用
#
# 维护约定：
# - 修好一条就删一条。加条目只允许发生在"严格门首次暴露闸门修好前就存在的失败"这一次性
#   锚定里；此后想让 PR 变绿必须改用例或改产品代码，或用 -skip-testing: 显式跳过并注明原因。
# - 证据：main@7ccc5ac（当前 main）+ PR #56@f71be62 + PR #56@ea16a7e 三轮同码 run 的全部
#   test job 日志与后两轮闸门自身的 NEW FAILURE 明细；收录门槛是跨轮复现 ≥2 次，或确定性
#   断言失败（1 次也收），或已出现在闸门明细/上一版基线里。XCUITest 的
#   `Failed to terminate com.aether.app.ios` 属 app teardown 噪声、xcresult 不计失败，不收。
# - main@c2005ea（PR #55 之前）里出现过、之后三轮都不复现的失败不收录——那是已经还掉的债，
#   例如 DesignSystemTests/testAetherIconAllCasesCount。
# - 下面每一条都早于本 PR：本 PR 只动 ci.yml 与 scripts/，没碰产品与用例代码。它们此前被
#   `grep -c '"failed"'` 这个恒为 0 的旧门静默放行。

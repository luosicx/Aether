# 已知失败用例基线（历史债锚定）
#
# 用法：scripts/check-xcresult-failures.sh 把本次 xcresult 里的失败用例与本文件比对，
# 命中基线 → 只告警放行；基线外的新增失败 → 直接判红。于是不再出现"CI 绿但用例在失败"，
# 也不必一次性修完所有历史债。
#
# 格式：`<label>:<TestClass>/<testMethod>`，label 与 ci.yml 传入的一致（iOS / macOS / UI）。
# macOS 两个分片共用 macOS label；用例换分片不影响本文件；方法名写不写 () 都识别。
# 两种粒度：
#   `macOS:FooTests/testBar`  精确到方法，用于确定性失败（断言写错、标识符缺失）
#   `macOS:FooTests/*`        整类豁免，仅用于超时类失败——同一批里每次触发的方法不同，
#                             按方法锚定会在换个受害者时误报红。整类豁免会掩盖该类新增
#                             的真实失败，所以能精确就不要用通配。
#
# 维护约定：
# - 修好一条就删一条。加条目只允许发生在"严格门首次暴露闸门修好前就存在的失败"这一次性
#   锚定里；此后想让 PR 变绿必须改用例或改产品代码，或按上面的约定用 -skip-testing: 显式跳过。
# - 来源：run 42978823892（PR #56，head f71be62）三个 test job 的完整失败明细
#   （iOS 50 / macOS 分片 1 有 42 / 分片 2 有 51），以及 run 42970786821 中本轮未复现的历史条目。
#   本 PR 只动 ci.yml 与 scripts/，没碰产品与用例代码，所以下面每一条都早于本 PR——
#   它们此前被 `grep -c '"failed"'` 这个恒为 0 的旧门静默放行。
